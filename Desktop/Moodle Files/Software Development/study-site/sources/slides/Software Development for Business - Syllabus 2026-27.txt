1. Course description / Introduction to the course 
 
 
This course is the foundational component of the System Architecture module in the BBA 
and BAIB programmes. It is about taking software from an idea to something that runs, 
installs and can be maintained — software design, version control, containerization and 
deployment — and it is the basis for later courses in Database Management and Design, 
Cloud Solutions and DevOps Management. It connects the technical disciplines of the 
degree to their use in a business context. 
This is not a programming course. It builds on prior programming experience and is 
concerned with what happens to code once other people work on it: within a team, 
deploying on an unfamiliar machine, and under a deadline. Students gain hands-on 
experience with tools used by professional teams on a daily basis, such as Git and 
Docker. 
Prerequisites: some prior programming experience in Python and a personal laptop the 
student can install software on. A little familiarity with running code and using a terminal 
is useful but not required. 
 
 
2. Learning objectives and competencies 
 
 
The course pursues four goals: 
• Mastery of software development fundamentals — software design principles, patterns 
and best practices for maintainable code. 
• Proficiency in essential tools and technologies — terminal usage, Git and version 
control, Docker and containerization, and server access and usage. 
• Development of practical skills — transferable skills built through hands-on exercises 
and a term-long project. 
• Preparation for effective collaboration — version control with Git and GitHub, and 
working in server and container environments. 
By the end of the course, students will be able to: 
1. Take an idea to a working, installable, tested Python program. 
2. Read code and say what is wrong with it. 
3. Work in the terminal fluently. 
4. Collaborate on a shared codebase through branches, pull requests and review, and 
explain why a team’s branching model follows from how often it ships.

3. Course format and methodological approach 
 
 
The course meets twice a week (see section 9).  
- 
Tuesday sessions lean theoretical — explanation and live coding, then a guided 
exercise 
- 
Friday sessions lean practical — a short input, then a lab. Each topic is introduced 
through a worked example — a piece of code, a terminal transcript or a diff — 
then the concept, then practice; one worked example runs through the whole 
term.  
- 
Four Practice sessions and Demo Day are given over to the group project. 
Working environment. The recommended setup either of: 
- 
WSL2 with Ubuntu on Windows 
- 
The native shell on macOS and Linux 
On either case, we recommend using VS Code and Docker. The toolchain used and 
assessed throughout is fixed: uv, ruff, mypy, pytest, typer, Git and GitHub, Docker 
and Docker Compose. A different editor or setup is allowed provided the automated 
checks pass; no support will be provided off the recommended path. 
Workload. Nineteen sessions of 2.5 hours (47.5 contact hours) and approximately 50 
further hours of autonomous work, most of it on the group project. 
In class. Attendance is recorded every session (section 5). Laptops and tablets are for 
academic use only. Disruptive behaviour is referred to programme management. Class 
materials are published on Moodle a few days before each session. 
 
4. Course content 
 
 
The course follows the software development lifecycle across five modules. 
• M1 — Starting a software project: the development lifecycle, Waterfall versus Agile, 
Scrum, and the anatomy of an installable Python project. 
• M2 — Clean code and testing: writing a program rather than a script, naming and 
structure, type checking, and test-driven development.

• M3 — Terminal and shell: the filesystem, pipes and redirection, text-processing tools,

• M4 — Git and version control: the commit model, branching and merging, conflicts

• M5 — Docker, and server usage and access: images and containers, Dockerfiles,

stages (see section 5) and worked on in the Practice sessions. A separate project brief 
on Moodle gives the full requirements.
