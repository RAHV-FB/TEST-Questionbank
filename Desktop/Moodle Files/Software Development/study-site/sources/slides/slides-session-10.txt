Small programs, joined
$ wc -l expenses.csv
421 expenses.csv
$ tail -n +2 expenses.csv | cut -d, -f3 | sort | uniq | wc -l
8
Each program does one thing. | sends what the left one prints into the right one.
That is the Unix idea, and it is fifty years old: write programs that do one thing well, and
that work together.

===== [slides-session-10.pdf] page 5 =====
Three streams, four symbols
Every program has stdin (in), stdout (out) and stderr (errors).
Symbol
Does
>
stdout into a file (overwrites)
>>
stdout appended to the end of a file
|
stdout of one into stdin of the next
2>
stderr into a file
$ uv run expenses report nosuch.csv > out.txt
could not read nosuch.csv      # stderr: not in out.txt

===== [slides-session-10.pdf] page 6 =====
The wrangling kit
Command
Does
head -n 3 · tail -n 3
first or last lines
tail -n +2
everything from line 2, skipping the header
wc -l
count lines
cut -d, -f3
column 3 of a comma-separated file
grep · grep -v · grep -c
keep, drop, count matching lines
sort · sort -rn · sort -t, -k4
sort; numeric, reversed; by column
uniq -c · uniq -d
count adjacent repeats; only the repeated
uniq only sees neighbours. It is always sort | uniq .

A script is saving a pipeline for re-running
#!/usr/bin/env bash
set -euo pipefail
file="$1"
tail -n +2 "$file" | cut -d, -f3 | sort | uniq -c | sort -rn | head -n 3
#!/usr/bin/env bash : which program runs this file
chmod +x : a statement that this file is a program (session 9)
"$1" : the first argument. Always quote it

===== [slides-session-10.pdf] page 14 =====
Arguments, conditions, loops
if [ "$#" -lt 1 ]; then                       # $# is the number of arguments
  echo "usage: $0 FILE" >&2                   # $0 stands for the script
  exit 2
fi
if [ ! -f "$1" ]; then                        # $1 is the first argument
  echo "error: $1 is not a file" >&2
  exit 1
fi
for file in *.csv; do
  echo "$file has $(wc -l < "$file") lines"   # $(...) is the output of a command
done

Exit codes are the return value
$ ./top.sh
usage: ./top.sh FILE
$ echo $?
2
$ ./top.sh nofile; echo $?
error: nofile is not a file
1
0 means success. Anything else is failure
Errors go to >&2 , so they are not mixed into the output
CI reads one thing: the exit code. That is what turns a step red

===== [slides-session-10.pdf] page 16 =====
set -euo pipefail : three silent failures
Letter
Without it
With it
-e
Script carries on after a failing command
Stops at the first failure
-u
$NAME typo expands to nothing
Error: unbound variable
-o pipefail
Pipeline's code is its last stage's
Fails if any stage fails
$ ./u.sh
./u.sh: line 3: NAME: unbound variable

===== [slides-session-10.pdf] page 19 =====
One trap, and what we skipped
set -e
counter=0
((counter++))          # exits the script, silently
counter=$((counter + 1))   # safe
((counter++)) evaluates to the old value, 0 , which -e reads as failure. Use $(( )) .
Not today: functions and trap (clean up on exit). Look them up when you need them. They
are not examined.
