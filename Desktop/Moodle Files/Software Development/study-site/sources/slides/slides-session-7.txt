    return matches_category and expense.amount >= minimum

What a type checker catches that a linter cannot
def largest_expense(expenses: list[Expense]) -> Expense | None: ...
largest = largest_expense(expenses)
print(largest.amount)
error: Item "None" of "Expense | None" has no attribute "amount"
Empty list → None → crash at 2 a.m.
The checker finds it before anyone runs the program.

Where does the I/O live?
        ┌─────────────────────────────┐
        │  shell: cli.py              │   reads files, prints, exits
        │  ┌───────────────────────┐  │
        │  │  core: pure functions │  │   data in → data out
        │  └───────────────────────┘  │
        └─────────────────────────────┘
Core: takes values, returns values. No open , no print , no sys.exit .
Shell: the only place that touches the world.

Exceptions or return codes?
Exception
Return code / value

 raise

 return None / empty
Crossing to the shell
translate to an exit code

===== [slides-session-7.pdf] page 18 =====
Catch only what you can handle
try:
    ...
except:                       # ← v0.1
    print("could not read " + path)
    sys.exit(1)
A bare except hides every bug: a typo, a missing import, Ctrl-C . All become "could not
read".
except (OSError, ValueError):     # ← v0.2: only the two we expect

===== [slides-session-7.pdf] page 19 =====
Fail loudly, at the boundary
Core: raises on bad input, never prints an error
Shell: catches it, prints to stderr, exits non-zero
try:
    expenses = read_expenses(path)
except (OSError, ValueError) as error:
    typer.echo(f"could not read {path}: {error}", err=True)
    raise typer.Exit(code=1)
Session 5's exit code, with the reason attached.
v0.2 still prints and exits inside report.py . Moving this to the edge is v0.3 .

===== [slides-session-7.pdf] page 20 =====
print is not logging
import logging
logger = logging.getLogger(__name__)
logger.warning("skipped malformed row %d in %s", line_number, path)
Has a level: debug · info · warning · error
Can be silenced, filtered, sent to a file: without editing the code
print is for the program's output; logging is for its diary
Configure once, in the shell: logging.basicConfig(level=logging.INFO) .
