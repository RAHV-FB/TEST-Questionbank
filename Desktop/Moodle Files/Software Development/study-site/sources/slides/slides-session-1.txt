What is Software Engineering?
Software Engineering is the systematic process of designing, developing, testing, and
maintaining computer software using scientific and engineering principles.
This goes beyond just writing code: it is the structured approach to ensure that programs are
reliable, secure, efficient, and easy to maintain over time.

Seven phases
1. Idea
2. Analysis
3. Design
4. Development
5. Testing
6. Deployment
7. Maintenance
The point is that following this sequence of
steps we build and protect the software
before users get to it.
The methodology lies in how we transition
from one phase to the next.
We will discuss all of them while working
through one example: an app to track

Idea: "We discover the mission: what do we want to create?"

Analysis: "We explore the terrain and gather tools."
Feature

List expenses
Show everything recorded
Summary by category
Total the spending in each category
Everything it will do, pinned down before the build starts.

===== [slides-session-1.pdf] page 17 =====
Design → Development → Testing
Design: the structure. How the pieces connect, how someone moves through it, how
software behaves.
Development: build it, from the design. Implement add, list and summarise. Wire them up.
Testing: verify it does what the analysis said. A checklist, run every time, not once.
Development arrives comparatively late. Three phases happen before anyone types code.
Notice how there is a lot of thinking about the code prior to writing the code itself.
Alberto Cámara | Software Development for Business | Session 1

===== [slides-session-1.pdf] page 18 =====
Deployment → Maintenance
Deployment: publish it, so someone who is not its author can actually use it.
Maintenance: fix bugs. Improve what is slow or ugly, keep it running. Forever.
Most software is maintained far longer than it is written.
We will treat software as a something that is living and evolving.
The lifecycle is not a finite set of steps that lead to a perfect program that will run forever
without being changed.
The only software that does not change is the one that stays forgotten on a shelf, without
ever running.
Alberto Cámara | Software Development for Business | Session 1

===== [slides-session-1.pdf] page 19 =====
How the cycle goes on
Eventually:
We will discover unintended behaviours (bugs)
We will have to add new behaviour (features)
Ensure that the software can connect to new components that replace old components, or
run on a different device (refactor)
Sometimes we will willingly leave things implemented in a way which is not the best
possible solution, knowing that at some point we will need to make an improvement (tech
debt)
In such cases, we start the cycle again, back to the Design phase.

The group project
Fifteen groups, four people each (two of them five), self-selected. One project, one
group, all term.
Every group builds a terminal program: no web, no GUI. You pick your topic from a
menu of fifteen.
One topic per group. No duplicates. Fifteen topics, fifteen groups, first come first
served, settled in session 2.
Every repository is public, deliberately.
